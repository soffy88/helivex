## 二、S3 归档 —— 唯一出路,以及为什么它是唯一出路

### 背景:CEX 爆仓数据整个品类结构性不可得(LER spec §13,已裁决)

| 来源 | 实测结论 |
|---|---|
| OKX `liquidation-orders` WS | **硬限流 ~1 笔/秒**。2,424 笔散在 2,415 个不同的秒,99.6% 的活跃秒恰好 1 笔;名义额最大的那分钟($2.63M)只推了 3 笔 → **限流指纹,非市场清淡** |
| Binance 官方历史归档 | **归档本身就是那条限流流**(实测每秒恰好 1 笔、100.0%、MAX=1) |
| Binance liquidationSnapshot | USDT 本位**已整体下架**;coin 本位只从 2023-06-25 起 |
| 各数据商(Coinalyze/CoinGlass…) | 只是把限流流加起来 —— 同一类错误,只是更贵 |

§13 的裁决原话:**"那份数据从未被广播,也不存在任何归档。不是'太贵',是'买不到'。"**

### 为什么 HL 不同

HL 是**链上**永续:每一笔强制平仓都落在 node 的 `node_fills` 里,带 liquidation 标记。
**没有 WS 限流这一层**——限流是交易所推送侧的产物,链上归档是全量的。这是目前已知的
**唯一非限流全市场强制流**。

### 成本估算 —— 现在测不了,但决策结构是清楚的

**测不了的原因**(诚实):`hl-mainnet-node-data` 与 `hyperliquid-archive` 匿名请求均返回
**HTTP 403**(requester-pays 需凭证);本机**无 aws cli、无 AWS 凭证**。真实测量要动用你的
AWS 账户并产生 requester-pays 费用 —— 这是你的决定,我没有擅自配置。

**S3 定价(us-east-1)**:

| 项 | 单价 |
|---|---|
| 传输出到互联网 | **$0.09/GB**(前 10TB/月;每月前 100GB 免费) |
| 同区域 EC2 传输 | **$0**(只付 GET 请求费) |
| GET 请求 | $0.0004 / 1,000 次 |

**决定性架构分叉**——同样的数据,两种拿法差一到两个数量级:

| 方案 | 传输费 | 其他成本 | 适用 |
|---|---|---|---|
| A. 直接下到本机 | 归档 GB × $0.09 | 无 | 归档小(<100GB)时可行 |
| B. 同区 EC2 处理后只回传结果 | **≈$0** | EC2 时长 + 少量 GET | 归档大(TB 级)时唯一合理 |

若归档是 1TB 量级:方案 A ≈ **$90 纯传输费**;方案 B 传输 ≈ **$0**,成本变成几小时 EC2
(spot 实例数美元)。**归档越大,B 的优势越绝对。**

### 建议:先做有界探针,不要先做全量决策

真正的未知只有一个:**归档每小时/每天多少字节**。这个可以用几分钱测出来:

1. 配一次性只读 AWS 凭证
2. `aws s3 ls --request-payer requester s3://<bucket>/node_fills/<某一天>/` —— 列一天,看文件数与字节数
3. 取 1 个小时的文件下来,量压缩后大小 + 解压后爆仓行数占比
4. 外推:目标窗口天数 × 每天字节 → 两个方案各自的总成本

**这个探针的成本是几分钱,不是几十美元**,且能把"要不要做 Phase 2"从猜测变成算术。
在拿到这个数字之前,任何"S3 贵不贵"的讨论都是空转。

数据线唯一的真问题是:**S3 归档每天多少字节**。
